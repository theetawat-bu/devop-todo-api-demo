# ⚙️ CI/CD — ระดับ 1: เริ่มต้น

> **เป้าหมาย:** อ่าน workflow ออก รู้ว่ามันรันเมื่อไร และแก้ให้ทำงานตามที่ต้องการได้
> **ต้องมีก่อน:** push repo ขึ้น GitHub แล้ว
> **เวลาโดยประมาณ:** 1–2 ชั่วโมง
> **อ่านประกอบ:** [docs/06 — GitHub Actions CI](../../docs/06-github-actions-ci.md)

---

### C1.1 ทำให้ CI รันครั้งแรก

**โจทย์:** push โค้ดขึ้น GitHub แล้วดูให้เห็นว่า workflow รันจริง
**ผ่านเมื่อ:** แท็บ Actions ขึ้นเขียว และบอกได้ว่าใช้เวลาทั้งหมดกี่วินาที

---

### C1.2 อ่าน workflow ให้ออก

**โจทย์:** เปิด `.github/workflows/ci.yml` แล้วตอบ 4 ข้อ — มีกี่ job, job ไหนรอ job ไหน, `services:` มีไว้ทำอะไร, ทำไมต้องมี `actions/checkout`
**ผ่านเมื่อ:** วาดแผนภาพลำดับการทำงานได้

---

### C1.3 ทำให้ CI แดงโดยตั้งใจ

**โจทย์:** ใส่ type error ลงในโค้ดแล้ว push
**ผ่านเมื่อ:** CI แดงที่ step `typecheck` และหาบรรทัดที่ผิดจาก log ได้ แล้วแก้ให้เขียวกลับ

---

### C1.4 แยก secret กับ variable

**โจทย์:** เพิ่ม secret ชื่อ `TEST_SECRET` และ variable ชื่อ `TEST_VAR` แล้วลองพิมพ์ทั้งสองค่าใน workflow
**ผ่านเมื่อ:** เห็น variable เป็นค่าจริงใน log แต่ secret ถูกปิดเป็น `***` — แล้วอธิบายได้ว่าควรใช้อันไหนกับอะไร

---

### C1.5 กำหนดว่าจะรันเมื่อไร

**โจทย์:** แก้ `on:` ให้ workflow รันเฉพาะเมื่อไฟล์ใน `src/` เปลี่ยนเท่านั้น
**คำใบ้:** `paths:` และ `paths-ignore:`
**ผ่านเมื่อ:** แก้ไฟล์ `.md` แล้ว workflow ไม่รัน แต่แก้ `src/` แล้วรัน

---

### C1.6 รันเองด้วยมือ

**โจทย์:** ทำให้กดรัน workflow ได้จากหน้าเว็บ
**คำใบ้:** เพิ่ม `workflow_dispatch:` ใน `on:`
**ผ่านเมื่อ:** เห็นปุ่ม **Run workflow** และกดรันได้จริง

---

### C1.7 อ่าน artifact และ summary

**โจทย์:** เพิ่ม step ที่เขียนข้อความลง `$GITHUB_STEP_SUMMARY` และ step ที่อัปโหลดไฟล์เป็น artifact
**คำใบ้:** `actions/upload-artifact@v4`
**ผ่านเมื่อ:** เห็นข้อความในหน้าสรุปของ run และดาวน์โหลด artifact ได้

---
