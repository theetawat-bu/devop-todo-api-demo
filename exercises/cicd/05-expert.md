# ⚙️ CI/CD — ระดับ 5: มืออาชีพ

> **เป้าหมาย:** ออกแบบกระบวนการส่งมอบซอฟต์แวร์ให้ทั้งทีม/องค์กร และวัดผลได้
> **ต้องมีก่อน:** ผ่านระดับ 4
> **เวลาโดยประมาณ:** 1–2 สัปดาห์
> ระดับนี้วัดที่ **ตัวเลขและเอกสาร** ไม่ใช่ YAML

---

### C5.1 วัด DORA metrics

**โจทย์:** วัด 4 ตัวชี้วัดของทีมคุณจากข้อมูลจริง

| ตัวชี้วัด | คำถามที่มันตอบ |
| --- | --- |
| Deployment Frequency | deploy บ่อยแค่ไหน |
| Lead Time for Changes | commit → ขึ้น production ใช้เวลาเท่าไร |
| Change Failure Rate | deploy กี่ % ที่ทำให้เกิดปัญหา |
| Time to Restore | พังแล้วกลับมาใช้ได้ในเวลาเท่าไร |

**ผ่านเมื่อ:** มีตัวเลขจริงจาก GitHub API + ระบบ incident แล้วเลือกมา 1 ตัวเพื่อปรับปรุงพร้อมแผน

---

### C5.2 ออกแบบกลยุทธ์ branch ให้ทีม

**โจทย์:** เลือกและเขียนเหตุผลระหว่าง trunk-based / GitHub flow / GitFlow สำหรับทีมของคุณ
**ต้องมีในเอกสาร:** ขนาดทีม, ความถี่ในการ release, ต้องรองรับหลายเวอร์ชันพร้อมกันไหม, ระดับความเป็นอัตโนมัติของเทส
**ผ่านเมื่อ:** ทีมนำไปใช้จริงได้ และมีคำตอบสำหรับ "แล้ว hotfix ทำยังไง"

---

### C5.3 นโยบายความปลอดภัยของ pipeline

**โจทย์:** ทำให้ครบทั้ง 5 ข้อ

- pin action ด้วย commit SHA ไม่ใช่ tag (tag ถูกย้ายได้)
- ตั้ง `permissions:` แบบ least privilege ทุก job
- ห้าม workflow จาก fork PR เข้าถึง secret
- ใช้ OIDC แทนการเก็บ credential ระยะยาว
- เปิด branch protection + required review + signed commits

**ผ่านเมื่อ:** ตรวจด้วย `zizmor` หรือ OpenSSF Scorecard แล้วคะแนนดีขึ้นจากเดิม

---

### C5.4 แผนย้ายจาก push-based ไป pull-based

**โจทย์:** เขียนแผนย้ายระบบที่ใช้ `kubectl apply` ใน CI อยู่ ไปเป็น GitOps โดยไม่หยุดการทำงานของทีม
**ต้องมีในแผน:** ทำเป็นเฟส, ช่วงที่รันคู่ขนานสองระบบ, เกณฑ์ตัดสินใจย้อนกลับ, แผนอบรมทีม
**ผ่านเมื่อ:** คนที่ไม่เคยใช้ Argo อ่านแล้วรู้ว่าต้องทำอะไรในสัปดาห์แรก

---

### C5.5 ทำให้ pipeline เชื่อถือได้

**โจทย์:** หา flaky test / flaky step ในระบบแล้วแก้
**คำใบ้:** เก็บสถิติ 50 run ล่าสุด หาว่า step ไหนแดงแบบสุ่ม
**ผ่านเมื่อ:** อัตราการ re-run ลดลงชัดเจน
**เหตุผลที่สำคัญ:** pipeline ที่แดงมั่ว ๆ จะสอนให้ทีม "กด re-run ไว้ก่อน" ซึ่งทำลายคุณค่าของ CI ทั้งหมด

---

### C5.6 ควบคุมต้นทุน

**โจทย์:** วัดว่าใช้ CI ไปกี่นาที/เดือน แล้วลดลง 30% โดยไม่ลดคุณภาพการตรวจ
**คำใบ้:** cache ให้ดี, ข้าม job ที่ไม่จำเป็นด้วย path filter, ใช้ runner ขนาดพอดี, ใช้ concurrency ยกเลิก run เก่า
**ผ่านเมื่อ:** มีตัวเลขก่อน-หลัง

---

### C5.7 เขียน platform docs ให้ทีม

**โจทย์:** เขียนเอกสารที่ตอบ 5 คำถามนี้ให้คนใหม่ในทีมอ่านเองได้
1. โค้ดของฉันเดินทางจากเครื่องฉันไปถึง production ยังไง
2. ถ้า CI แดงต้องทำยังไง
3. deploy ยังไง ใครอนุมัติ
4. พังแล้วต้อง rollback ยังไง
5. จะเพิ่มบริการใหม่ต้องทำอะไรบ้าง

**ผ่านเมื่อ:** คนใหม่อ่านแล้ว deploy ครั้งแรกได้เองภายในวันแรกโดยไม่ต้องถามใคร
เกณฑ์นี้แหละคือมาตรวัดที่แท้จริงของงาน platform
