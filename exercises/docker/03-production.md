# 🐳 Docker — ระดับ 3: ใช้งานจริง

> **เป้าหมาย:** ทำ image ที่กล้าเอาขึ้น production — ปลอดภัย จำกัดทรัพยากรได้ ปิดตัวอย่างสุภาพ
> **ต้องมีก่อน:** ผ่านระดับ 2
> **เวลาโดยประมาณ:** 4–8 ชั่วโมง

---

### D3.1 ยืนยันเรื่อง non-root

**โจทย์:** พิสูจน์ว่า container เขียนไฟล์นอก `/app` ไม่ได้
**คำใบ้:** `docker exec -it <c> sh` แล้วลอง `touch /test`
**ผ่านเมื่อ:** ได้ `Permission denied` แล้วอธิบายได้ว่าถ้ารันเป็น root จะเสี่ยงยังไงเมื่อแอปมีช่องโหว่ RCE

---

### D3.2 read-only root filesystem

**โจทย์:** ทำให้ container รันได้ด้วย `--read-only`
**คำใบ้:** จะพังตรงที่เขียน `/tmp` ไม่ได้ → เพิ่ม `--tmpfs /tmp`
**ผ่านเมื่อ:** แอปทำงานปกติทั้งที่ root fs เขียนไม่ได้ แล้วเปิด `readOnlyRootFilesystem: true` ใน `k8s/base/api.yaml` ตามไปด้วย

---

### D3.3 memory limit และ OOMKilled

**โจทย์:** รันด้วย `--memory=64m` แล้วทำให้มันโดนฆ่า
**คำใบ้:** ยิงโหลดหนัก ๆ หรือเขียน endpoint ที่จองอาร์เรย์ใหญ่ ๆ
**ผ่านเมื่อ:** เห็น exit code **137** และอธิบายได้ว่ามาจาก 128 + สัญญาณที่ 9 (SIGKILL) — แล้วบอกได้ว่าทำไม OOM ถึงไม่มี graceful shutdown ให้

---

### D3.4 CPU limit และ throttling

**โจทย์:** รันด้วย `--cpus=0.2` แล้วยิงโหลด เทียบเวลาตอบกับตอนไม่จำกัด
**ผ่านเมื่อ:** มีตัวเลขเทียบได้ และอธิบายความต่างสำคัญ — เกิน CPU limit แค่**ช้าลง** แต่เกิน memory limit **ตาย**

---

### D3.5 สแกนช่องโหว่แล้วแก้จริง

**โจทย์:** สแกน image ด้วย Trivy แล้วทำให้ HIGH/CRITICAL ลดลง
**คำใบ้:**

```bash
docker run --rm -v /var/run/docker.sock:/var/run/docker.sock \
  aquasec/trivy image devops-todo-api:local
```

**ผ่านเมื่อ:** มีตัวเลขก่อน-หลัง และแยกได้ว่ารายการไหนมาจาก base image รายการไหนมาจาก npm package ของเรา (วิธีแก้คนละแบบ)

---

### D3.6 pin base image ด้วย digest

**โจทย์:** เปลี่ยน `FROM node:22-alpine` เป็นแบบระบุ digest
**คำใบ้:** `docker inspect --format='{{index .RepoDigests 0}}' node:22-alpine`
**ผ่านเมื่อ:** build ผ่าน และอธิบายได้ว่าทำไม tag เฉย ๆ ถึงไม่ปลอดภัย (คนอื่น push ทับ tag เดิมได้) — พร้อมบอกข้อเสียของการ pin ด้วย (ต้องอัปเดตเองเมื่อมี security patch)

---

### D3.7 ทดสอบ graceful shutdown ด้วยนาฬิกา

**โจทย์:** วัดเวลาที่ใช้ในการ `docker stop` สองกรณี — มี SIGTERM handler กับไม่มี
**คำใบ้:** `time docker stop <c>` แล้วลองคอมเมนต์ `process.on('SIGTERM', ...)` ใน `src/index.ts` ออกชั่วคราว
**ผ่านเมื่อ:** เห็นความต่างชัด (ไม่ถึงวินาที vs รอครบ 10 วิ) แล้วเชื่อมโยงกับ `terminationGracePeriodSeconds` บน k8s ได้

---

### D3.8 ไม่ให้ความลับหลุดเข้า image

**โจทย์:** ตรวจว่า image ปัจจุบันมีความลับติดอยู่ไหม
**คำใบ้:** `docker history --no-trunc`, `docker save t | tar -x` แล้วค้นหา, หรือใช้ `trivy image --scanners secret`
**ผ่านเมื่อ:** ยืนยันได้ว่าไม่มี และอธิบายได้ว่าทำไม `ENV SECRET=xxx` หรือ `COPY .env .` ถึงอันตราย แม้จะ `RUN rm` ทีหลังแล้วก็ตาม

---

### D3.9 log ให้ระบบอ่านได้

**โจทย์:** ตรวจว่า log ของแอปออกทาง stdout เป็น JSON บรรทัดเดียวหรือไม่ ถ้ายังไม่ใช่ให้แก้
**ผ่านเมื่อ:** `docker logs` แล้วนำไป `jq` ได้ทันที และอธิบายได้ว่าทำไมไม่ควรเขียน log ลงไฟล์ใน container

---
