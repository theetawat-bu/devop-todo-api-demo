# 00 — Roadmap การเรียนรู้: จากศูนย์ถึง deploy จริง (ฟรี + scale ได้)

เอกสารนี้เป็น**แผนที่รวม** — ไม่มีเนื้อหาใหม่ แค่บอกว่าเรียงยังไง ใช้เวลาเท่าไร และจะรู้ตัวยังไงว่า "พร้อมไปขั้นถัดไป"
ถ้าไม่รู้จะเริ่มจากไหน เริ่มที่นี่ก่อน แล้วค่อยกดลิงก์เข้าไปอ่านแต่ละบท

## ภาพรวมเส้นทาง

```
รันในเครื่อง → ห่อเป็น container → ต่อหลาย service → proxy คั่นหน้า
     → CI ตรวจโค้ดอัตโนมัติ → CD ส่งของอัตโนมัติ → Kubernetes
     → deploy ขึ้น cloud ฟรีจริง → scale
```

แต่ละขั้นตอบคำถามที่ขั้นก่อนหน้าทำให้เกิด — ห้ามข้าม โดยเฉพาะถ้าไม่เคยทำ DevOps มาก่อน

## ระยะที่ 3 — ขึ้นจริงบนคลาวด์ฟรี + scale

นี่คือคำตอบตรง ๆ ของคำถาม **"deploy ลง server ฟรีได้ไหม แล้ว scale ยังไง"**

| ขั้น | เอกสาร | ใช้เวลาโดยประมาณ | รู้ว่า "ผ่าน" เมื่อ |
| --- | --- | --- | --- |
| 9 | [13 — อ่านสคริปต์ deploy](13-reading-scripts.md) | 1 ชม. | อ่าน workflow bash script ของคนอื่นแล้วบอกได้ว่าทำอะไร |
| 10 | [10 — Deploy ขึ้น cloud ฟรี](10-deploy-free-cloud.md) | ครึ่งวัน–1 วัน | มี URL จริงที่ยิงจากอินเทอร์เน็ตได้ ไม่เสียเงิน |

**10 มีคำตอบเรื่อง scale อยู่ในตัว** — เลือกได้ 3 เส้นทาง:

| เส้นทาง | ที่ไหน | Scale ยังไง | ฟรีแค่ไหน |
| --- | --- | --- | --- |
| 🅰️ PaaS (ง่ายสุด) | Render / Koyeb + Neon | ปรับ instance count ในหน้าเว็บ ไม่ต้องแตะ config | ฟรีมีข้อจำกัด (sleep เมื่อไม่มี traffic บาง tier) |
| 🅱️ Kubernetes จริง | k3s บน Oracle Cloud Always Free | `HPA` scale ตาม CPU อัตโนมัติ (2-6 pod) — [ดู hpa.yaml](../k8s/base/hpa.yaml) | Always Free ตัวเครื่อง แต่ต้องดูแลเอง |
| 🅲 K8s ใน GitHub Actions | k3d ชั่วคราวใน CI | ใช้ฝึก workflow เฉย ๆ ไม่ใช่ปลายทาง production | ฟรี 100% แต่ไม่มี URL ถาวร |

**คำแนะนำสำหรับมือใหม่:** เริ่ม 🅰️ ก่อนเพื่อให้มี URL ใช้งานได้เร็วที่สุด แล้วค่อยไปทำ 🅱️ เมื่ออยากเข้าใจ Kubernetes จริงจัง
🅱️ คือทางที่ตอบโจทย์ "scale แบบง่าย ๆ" ที่สุด เพราะ HPA จัดการให้อัตโนมัติทั้งหมด สิ่งที่ต้องทำมีแค่ตั้ง `resources.requests` ให้ถูก (ดู [08 — HPA](08-kubernetes.md))

**เช็คพอยต์ระยะที่ 3:** มี URL จริงบนอินเทอร์เน็ต, ลองยิง load เข้าไปแล้วเห็น pod เพิ่มจำนวนเองผ่าน `kubectl get hpa -w`

## ระยะที่ 4 — ถ้าทำงานในองค์กรที่มี infra ของตัวเอง

| ขั้น | เอกสาร | เมื่อไรควรอ่าน |
| --- | --- | --- |
| 11 | [11 — Enterprise GitOps](11-enterprise-gitops.md) | เมื่อบริษัทมี private registry (เช่น **Harbor**) + Argo CD + cluster หลัง VPN — ไม่ใช่ทุกคนต้องอ่าน แต่ถ้าเจอ Harbor ในงานจริง บทนี้อธิบายว่ามันคืออะไร ใช้ทำไม และจำเป็นแค่ไหน |

**สั้น ๆ ก่อนเปิดอ่าน 11:** Harbor **ไม่จำเป็น**สำหรับ deploy ฟรีในระยะที่ 3 — GHCR (ที่ใช้ใน 07/10) ก็เพียงพอสำหรับโปรเจกต์ส่วนตัวหรือทีมเล็ก
Harbor เข้ามาเมื่อองค์กรต้องการ registry ของตัวเอง (ไม่พึ่ง cloud ภายนอก, สแกนช่องโหว่เอง,ควบคุม retention เอง) — รายละเอียดเต็มอยู่ใน [11](11-enterprise-gitops.md)
